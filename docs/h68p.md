# H68P — trusted detection blob

H68P is the **device-bound, signed detection plugin** for het68. The platform
firmware (USB audio, I2S, CLI, Secure loader) is one image; detection can ship
as a separate blob that only that chip will accept.

Lab default (1.26.x): detection is still **linked into the platform**
(“builtin”). A valid H68P in flash is verified as a gate; Core1 only loads the
blob into Secure SRAM when built with `HET68_PLUGIN_EXTERNAL=1`.

Related: [secure-boot-lab.md](secure-boot-lab.md) (OTP / platform seal),
[signing/README.md](../signing/README.md), headers `h68p.h` / `het68_flash_map.h`.

## Why a separate blob

| Goal | How H68P helps |
|------|----------------|
| Ship one platform UF2 to many devices | Detection updates without reflashing USB/I2S |
| Bind detection to a physical chip | Header embeds the 8-byte OTP board id |
| Integrity / authenticity | SHA-256 of payload + ECDSA secp256k1 (same curve family as RP2350 boot) |
| Anti-downgrade | `rollback` counter; loader prefers the higher valid slot |

Signing a blob does **not** change the GPL-3.0 licence of detection sources
(`doa.c` / `neo_srp.c` / …).

## On-wire / on-flash layout

Little-endian. Total size = header + payload + signature.

```
┌──────────────────────────────┐
│ h68p_header_t (76 bytes)     │  magic 'H68P', ABI, sizes, serial, hashes…
├──────────────────────────────┤
│ payload (code / rodata)      │  code_size bytes
├──────────────────────────────┤
│ ECDSA secp256k1 sig (64 B)   │  r‖s over SHA-256(header ‖ payload)
└──────────────────────────────┘
```

### Header fields (`h68p.h`)

| Field | Meaning |
|-------|---------|
| `magic` | `0x50383648` (`'H68P'` LE) |
| `version` / `api_abi` | Container / plugin ABI (both `1` today) |
| `code_size` | Payload length |
| `entry_off` | **Even** byte offset of Thumb entry in payload (loader ORs the Thumb bit) |
| `bss_size` | Secure BSS the plugin expects (cleared on external load) |
| `rollback` | Monotonic anti-downgrade; newer wins across A/B slots |
| `device_serial[8]` | Must equal `pico_get_unique_board_id()` |
| `payload_sha256[32]` | SHA-256 of payload only |
| `hdr_crc32` | CRC-32 of the header bytes before this field |

Public key in firmware is **64-byte uncompressed X‖Y** (no SEC1 `0x04` prefix),
embedded as `HET68_H68P_PUBKEY` in `h68p_pubkey.c`.

### Loader checks (fail → no external Core1 / `DET PLUGIN invalid`)

1. Magic, version, ABI, sizes, even `entry_off`
2. Header CRC + payload SHA-256
3. OTP serial match
4. secp256k1 verify of SHA-256(header ‖ payload)

## Flash map (Pico Plus 2 W, 16 MiB)

```
0x10000000 ── platform IMAGE (UF2) ──► must stay below plugin slots
             … H68P slot0 (512 KiB) …
             … H68P slot1 (512 KiB) …
             … ACID tail (DRONE/BT/DET/ENT) …
flash end
```

Constants: `het68_flash_map.h`. ACID offsets are unchanged. Upload stages into
PSRAM past the 6 MiB DOA ring, then programs a slot only while USB audio is idle
(same discipline as ACID stores). After each `flash_safe_execute`, the firmware
calls `het68_psram_restore()` so QMI CS1 / the ring stay valid.

## Build / sign / upload

```bash
./scripts/gen_dev_keys.sh          # lab secp256k1 PEM (gitignored)
./build.sh                         # platform UF2 + build/het68_detect.bin stub
# serial= from UART STATUS / USB string (16 hex digits)
./scripts/sign_plugin.py \
  --payload build/het68_detect.bin \
  --serial <16hex> \
  --key signing/dev_secp256k1.pem \
  --out build/het68_detect-<serial>.h68p \
  --entry-off 0
```

On the device (CDC / probe UART), USB capture idle (`alt=0`):

```
DET PLUGIN WRITE
H68PHEX <hex…>
…
DET PLUGIN END
DET PLUGIN STATUS
DET PLUGIN ERASE          # wipe both slots (queued for idle)
```

Host smoke (no hardware): `python3 scripts/test_h68p_roundtrip.py`.

## Runtime modes (CMake)

| Flag | Default | Behaviour |
|------|---------|-----------|
| `HET68_PLUGIN_EXTERNAL` | OFF | OFF = builtin DOA linked; ON = load verified H68P into Secure SRAM @ `0x20040000` |
| `HET68_PLUGIN_REQUIRED` | OFF | OFF = missing/invalid H68P still starts builtin; ON = refuse Core1 without a valid blob |
| `HET68_SAU_PROGRAM` | 0 | SAU register writes off until dual-ELF NS image exists |

PSRAM 6 MiB ring stays Non-secure so Core0 can `doa_ring_push` without an NSC
per sample. Detection results can be published through the Secure→NS mailbox
(`secure/mailbox.c`).

## Trust boundary (lab vs production)

- **Lab:** platform may be unsigned; H68P still uses the lab public key; **SWD/UART stay enabled**.
- **Production path:** seal platform (`scripts/seal_platform.sh`), then OTP
  `BOOTKEY*` / `SECURE_BOOT_ENABLE` per [secure-boot-lab.md](secure-boot-lab.md).
  OTP is irreversible; do not burn debug-disable until you mean it.
